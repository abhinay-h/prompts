### Strict Architecture & Design Rules:

1. **Layer Structure in `shared/common/[FEATURE_NAME]/`**:
   - `query-keys.ts`: Pure const key arrays and key factory functions with zero runtime dependencies.
   - `query-options.ts` (or `queries.ts`): Export `queryOptions(...)` factories, query specs, retry/enabled rules, and cache invalidation helpers.
   - `types.ts`: Domain models and query parameter types shared between platforms.

2. **Clean Platform Separation (Zero Leakage)**:
   - Shared query options MUST NOT import platform-specific dependencies:
     ❌ No `cookies()`, Next.js server-only code (`next/headers`, `next/navigation`).
     ❌ No `expo-secure-store`, `@react-native-async-storage`, `Linking`, `Alert`, or React Native primitives.
     ❌ No UI side effects (no toasts, redirects, or component state).
   - In shared query option factories, allow client-injected query functions or parameterized fetchers so Web (cookies/proxy) and Mobile (Bearer headers) can supply their platform fetcher safely if signatures differ.

3. **Query Implementation Standards**:
   - Centralize duplicate query keys and options if they exist separately on Web and Mobile.
   - If Web or Mobile components are using manual `useEffect` + `useState` + fetch calls, migrate them to TanStack Query (`useQuery` / `useMutation`).
   - Preserve standard cache defaults: `staleTime: 60 * 1000` (or feature-specific cadence like 30s for live tracking), `retry` filters (do not retry 4xx errors).
   - Always define explicit `enabled` conditions to prevent invalid unscoped fetches.

4. **Negative Constraints**:
   - 🚫 DO NOT introduce TanStack Table or TanStack DB.
   - 🚫 DO NOT modify backend Go/Node endpoints or change existing API contracts.
   - 🚫 DO NOT break Server Component hydration or SSR prefetching on Web.
